# Architecture checklist

Normally, architecture checklist will depend on who stakeholder of the system is and how design needs to be documented. To me, architect has to deal with non-functional requirements and design according to prioritized list of such. Then design is decomposed into multiple views depending on granularity required. This is a simplified idea of "Views and beyond" approach from SEI university: https://resources.sei.cmu.edu/library/asset-view.cfm?assetid=484159

Generally, architecture should include at least: resource allocation view, module view and component-and-connector view. This should be enough to display most of the decisions performed by the architect.

However, if your system is simple enough, there is well-known "12-factor app methodology" that you can try using: https://en.wikipedia.org/wiki/Twelve-Factor_App_methodology. It has some sort of a checklist, that you can follow.
